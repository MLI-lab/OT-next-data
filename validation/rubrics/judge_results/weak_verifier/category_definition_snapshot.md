# VERIFIER-TOO-WEAK

**Definition in rubric:**

The verifier passes without the task actually being solved: it does not check one or more requirements stated in the instructions, it checks only output shape/format/types/count, trusts a self-reported value, greps the source for keywords, checks a hardcoded subset, or tests only fixed inputs so the answer can be hardcoded. A fabricated, plausibly-shaped output would pass.

We want ground-truth examples where an agent can receive **reward 1 with a plausible but incomplete or incorrect solution**, without interfering with grading. We distinguish:

- **Weak verification:** The grader fails to check whether the agent fulfilled the task requirements.
- **Verifier exploitation:** The agent can interfere with the grading mechanism itself.

Manual task-by-task review gives **18 active FAIL examples and 16 PASS edge cases** for testing judges. FAIL means a plausible but incomplete or incorrect solution receives credit. PASS means the reviewed issue is verifier exploitation or a related exploit outside this check’s scope—not that the task is clean overall. The remaining two examples are held out or excluded below.

We added **`script_execution_coverage`** after reviewing TMax task `task_000233_ee5f0e33`, whose required report script is never run by the verifier. It checks whether a script requested in the instructions is executed by the verifier (following subprocesses and import/call chains). It flagged **3 of 37 examples**, including **2 of the 19 primary examples**.
